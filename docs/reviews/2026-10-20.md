**Límite de producción:** el contrato actual es académico y no define autenticación/autorización para las altas o lecturas. CORS no autentica clientes. La exposición pública de direcciones y operaciones requiere una frontera de acceso explícita antes del despliegue. Los listados actuales son completos y carecen de paginación; validar un contrato paginado antes de crecimiento sin límite. Son decisiones pendientes de despliegue/evolución, no cambios silenciosos de esta API 0.1.0.

**Observación de dependencias backend:** npm audit completa informa veinte avisos moderados transitivos de herramientas de pruebas asociados a sprintf-js; `npm audit --omit=dev` informa cero. [El aviso oficial no publica una versión corregida](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). No aplicar los downgrades mayores sugeridos por audit sin revisar compatibilidad.

**Revisión de persistencia:** Orders usa SQL parametrizado y transacción para alta/lectura del registro; la unicidad de zonas se apoya en la función SQL además de la consulta previa de aplicación. No se identificó N+1 en estos listados. No se certifican concurrencia, permisos SQL, índices ni rollback reales sin ejecutar el paquete PostgreSQL.
